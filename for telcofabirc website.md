## Detailed Description

### 5G ISAC Configuration

* **RAN Vendor:** 
  * OAI-7.2 fronthaul
* **Antenna Array:** 4 external-antenna setup
* **UE:** Google Pixel 7

### Dataset Scenario

| Attribute | Specification |
|---|---|
| **Environment** | Laboratory, indoor |
| **Sensing Target** | Single UE & Multi-UE |
| **Line-of-Sight (LoS)** | Normal operation and targeted human-blockage disturbances |
| **Mobility** | U-shape walking paths and stationary points |
| **Processing** | Real-time extraction of CIR taps and frequency-domain amplitudes |

---

## Processed Features vs. Raw I/Q Signals

Please note that the `.jsonl` files in this repository contain **pre-processed spatial features**, NOT raw I/Q signal samples. To optimize system performance and make the data **immediately ML-ready**, the raw I/Q files generated by the O-RAN xApp are processed in real-time by a Python data pipeline.

---

## Training Model (`labphy_env.json`)

This file contains the raw environment capture (large time-series of samples) used for training the localization models.

### Data Collection & Processing
* **Collection:** Raw SRS IQ files are written by the C xApp into the configured `DATA_DIR`. A Python worker reads the 4 antenna files that share the same timestamp, merges them into one sample, and collects labeled data.
* **Feature Engineering:** The system builds a 32-D training feature vector per sample:
  * `cir_feat` (24 dims): Normalized PDP taps (16 taps) + per-antenna relative phase encoded as cos/sin values.
  * `db_raw` (4 dims): Raw antenna energy values in dB.
  * `dx`, `dy`: Energy differences across the antennas.
  * `mean_db`, `max_db`: Computed from the raw dB values.
* **Outputs:** The training script produces a trained RandomForestRegressor (`rf_regressor_v26.pkl`), a fitted StandardScaler (`scaler_v26.pkl`), and a metadata file recording feature specs and evaluation metrics. The scaler ensures live inference is consistent with training data normalization.

## Real Test Datasets

### 1. `detection_dataset.jsonl` (Real-Time SRS Plot)
**Description:** Optimized for high sampling rates and minimal file I/O overhead, this dataset captures essential frequency-domain signatures to instantly detect sudden physical disturbances (e.g., human movement or blockages) in the sensing environment without needing full time-domain CIR arrays.
* **Key Features:** `timestamp`, `db` (Total received power across 4 antennas), `amp_db` (Frequency-domain amplitude), and `phase` (Subcarrier phase angles).
* **Test Scenario:** The UE is initially positioned near Antenna 3 with two human walk-by events, followed by relocation near Antenna 1 with another walk-by event.
* **Usage:** Plot the timestamp against the 4 `db` values to observe sudden dips indicating LoS blockages, or visualize `amp_db` / `phase` waterfalls to observe frequency-selective fading.

### 2. `dataset_single_ue.jsonl` (Single-UE Localization)
**Description:** Maps complete radio channel profiles to physical ground-truth coordinates. Used to train and evaluate core machine learning models for estimating 2D positions and Angle of Arrival (AoA) based on multipath propagation characteristics.
* **Key Features:**
  * **Output Labels:** `x` / `y` (Coordinates in meters), `target_angle_deg` (AoA), `quadrant`.
  * **ML Inputs:** `cir_feat` (24-D spatial fingerprint), `db` / `db_raw` (Median-smoothed total received power), `dx` / `dy` (Power differentials).
  * **Stability Metrics:** `energies`, `db_raw_instant`, `db_jump_max`, `pred_reject` (Filtering flags for noisy SRS frames).
* **Test Scenario:** The UE is carried continuously along a U-shaped walking trajectory around the lab, ending near the door.
* **Usage:** Extract the `x` and `y` coordinates and plot them on a 2D scatter plot to visualize the physical trajectory.

### 3. `dataset_multiues.jsonl` (Multi-UE Spatial Tracking & Collision Detection)
**Description:** Extends baseline localization by introducing user multiplexing to handle simultaneous signal reflections and transmissions from multiple devices, challenging the tracking algorithms to resolve spatial ambiguities.
* **Key Features:** Contains all core spatial features (`cir_feat`, `energies`) but with overlapping signatures. Includes `ueid` (User Equipment Identifier) for isolating multiplexed targets, and `heatmap` (`x`, `y`, `prob`) indicating the model's spatial probability distribution.
